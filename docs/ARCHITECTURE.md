# 架构

藏页是单人本机应用：FastAPI 提供 REST 接口，静态 HTML/CSS/JavaScript 提供阅读界面，SQLite 保存材料身份、版本、状态、批注、任务和推送记录。正文采集与收藏枚举各有一个串行工作者。默认监听 `127.0.0.1`，不提供远程多用户服务。

## 数据与任务

`app/adapters.py` 规范来源链接并路由适配器。`app/platform_browser.py` 使用本人保存的平台会话读取网页，`app/heybox.py` 处理图集与文章两种 DOM；`app/xbookmarks.py` 处理 X 书签，`app/video_pipeline.py` 依次尝试字幕与本机音频转写。平台验证或权限失败保留原因，不保存导航页冒充原文。

`app/heybox_api.py` 专门归一化小黑盒收藏接口。网页负责正常登录与请求签名，采集器只接收指定只读接口的返回条目，校验账号、offset连续性和末页；不猜测或枚举帖子ID。列表摘要不当成完整原文，正文只为新身份排队。正常网页停止在短页时最多核对一个实际next offset，不自造签名，拒绝或超时就保留未完成。接口缺失时兼容回退仅限专用收藏容器，不能从整个main或推荐流捡链接。

可选补齐模式将本次接口返回的旧未完成材料交给同一个采集队列，续读时也可补齐已登记但暂停的来源；本轮重复ID只登记一次。已完成、回收和永久删除记录不会被批量重采。验证前已收到的有效分页先保存，再停止；分页末尾和正文成功分别记录。

小黑盒正文与收藏读取连接本工具拥有的同一 Chrome 资料目录。`sessions.background_reader` 创建并复用一个最小化的专用读取窗口，不激活或移动常用 Chrome；普通完成清空读取页并撤去路由，平台验证时保留实际失败页。本人明确打开验证入口才恢复该窗口。共享读取窗口从取得到清理结束均按平台互斥，收藏清单、正文和本人登录操作不会同时导航同一标签。登录快照的注入记录使用稳定的浏览器端口和 debugger path，读取标签元数据改变不会再覆盖平台更新过的 Cookie。平台切换只是前端筛选，不停止持久化任务；队列停止需要显式请求。并不宣称采集完全不需要浏览器进程。

图片缓存任务优先复用已存附件，旧失败链接仅凭本条媒体记录恢复为图片，不改写原文含义。空图片地址触发来源重读；懒加载仍未返回地址时保留缺图计数。正文完整性未知或明确不完整时，补图不能把材料升级为完整成功。

`assets.localize` 一次材料处理共用 HTTP 连接池，每次请求与重定向前清理响应 Cookie，图片主机不接收平台凭据。前端 `imageLayout` 按内容类型和平台选排版：文章插图保持阅读宽度，图集为缩略图，`media.js` 负责页内全图查看。

图片任务因修订变化重排时，仅在正文和来源元数据快照未变的情况下继承本次完整性依据，保存新批注不会使完整旧正文退化；来源变化则重新判断。读取发生平台验证错误后，即使撤路由或断开连接失败也保留原验证异常，使队列仍进入平台暂停分支。

`app/store.py` 是本地状态源。原始来源与独立第一层材料分表保存；采集状态和处理状态分开。重新采集保留旧版本、批注和处理状态，正文变化会使不再适用的整理结果失效。任务队列及逐页进度可追溯；断点续读与新一轮最新收藏核对是不同操作。

同一规范来源只对应一条原始记录。永久删除在 `retired_sources` 留下规范来源的 SHA-256 指纹、原 ID、平台和时间；这张来源指纹表不含原文或链接，同步跳过该指纹。永久删除清理本条托管文件与独占缓存；已经确认的推送回执、非托管 outbox 导出、独立第一层记录和备份仍可能保有副本，不宣称所有历史副本都被抹除。远端不再收藏不触发本地删除。旧版本确有删除事件和本机备份时，可恢复来源指纹；没有历史证据时不能凭空重建。

个人运行目录为 `data`，包括数据库、按平台和材料 ID 分开的来源包、字幕、图片、版本、处理结果、模型、会话和本机 outbox。它们都在 `.gitignore` 中；代码仓库不带示例收藏数据库或真实内容。

B站收藏夹通过当前会话的导航身份和自建夹接口读取。`folder_ids` 放入任务 payload 与进度，续读保留原选择和顺序，API排序变化或新增夹不会改变旧断点范围；账户变化或夹不可访问会停止。同一视频按 BVID 去重，收藏夹出处合并到 `favorite_folders`，不会重复生成原文。

## 处理与材料包

第一步依据原文和本人批注，分别生成调用资料或消化暂存的独立记录，不要求 AI。第一层处理记录保留来源快照、方向和批注版本；原始来源仍可回看。之后可在这一层自己加工，或主动让 AI 结合明确选择的相关笔记整理，结果先待本人审查。

`app/obsidian.py` 管理 Markdown 知识库根和相对目录，`app/knowledge.py` 只读取本人选定目录/笔记，不递归扫描整库。二级默认进入主题下的材料专区，人工知识稿是另一项明确选择，不自动改写既有正文。界面的原文导读由 `app/reading_preview.py` 计算，保留主体与相邻段落。可选概要由 `app/overview.py` 在显式请求后运行，`reading_overviews` 独立缓存源哈希、结果、模型与时间；不修改材料的 summary、批注、原文或修订，也不进入后续 AI 或导出。任务冻结来源及模型配置哈希，生成期间变化会拒绝保存；长来源逐段概括后综合。

`app/task_status.py` 在只读快照事务中汇总全部进行中任务，结果列表有显示上限，统计没有旧 /jobs 的200条上限；最近一次同来源同类型尝试控制需处理状态，旧历史仍留存。`web/tasks.js` 独立于材料筛选与导入窗口每3秒轮询，断线保留上次状态并提示连接中断，不把断线冒充结束。仅概要片段刷新，不重建播放器或批注编辑器。

推送分两步：预览冻结版本、Markdown、附件清单、路径及哈希；确认核对哈希、材料修订、相关笔记及目录配置后才写入。预览后批注、目录或原文改变需要重新预览。确认有幂等回执，本机导出与真正外部系统执行状态分开。

`app/vault_files.py` 记录每份已确认包的具体文件和 SHA-256，迁移、回收、恢复、永久删除只操作这些归属明确的文件。文件日志和 SQLite 共同记录提交状态，中断后恢复；人工修改、共享附件、同名冲突、链接越界会停止。迁移更新本包相对图片与来源链接，核对后清理旧托管位置；不删除其他材料仍在使用的文件。

## 信任边界

平台页面、评论、字幕、模型结果都是不可信来源内容，不是工具执行指令。正文显示转义 HTML，外部链接及下载地址检查协议与公网地址，托管路径只允许知识库内普通相对目录。写请求验证本机来源和 `X-Local-Request` 请求头。登录态不进入 Markdown、AI 输入或公共 API 响应。

Windows 会话使用 DPAPI 加密；Chrome 扩展只在本人点击时读取所选平台 Cookie，直接交给本机服务。`chrome_bridge` 生成十分钟单次使用的平台连接码，成功保存后消费；CORS 仅对 `/api/accounts/browser-connect` 接受 Chrome 扩展 Origin，其他写接口仍限同源。扩展安装时无网站权限、无后台或内容脚本，也不导出 Cookie 文件。平台校验仍在实际访问时完成，Cookie 文件存在不代表登录有效或已读完全部收藏。
