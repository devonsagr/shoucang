# 架构

藏页是单人本机应用：FastAPI 提供 REST 接口，静态 HTML/CSS/JavaScript 提供阅读界面，SQLite 保存材料身份、版本、状态、批注、任务和推送记录。正文采集与收藏枚举各有一个串行工作者。默认监听 `127.0.0.1`，不提供远程多用户服务。

## 数据与任务

`app/adapters.py` 规范来源链接并路由适配器。`app/platform_browser.py` 使用本人保存的平台会话读取网页，`app/heybox.py` 处理图集与文章两种 DOM；`app/xbookmarks.py` 处理 X 书签，`app/video_pipeline.py` 依次尝试字幕与本机音频转写。平台验证或权限失败保留原因，不保存导航页冒充原文。

`app/heybox_api.py` 专门归一化小黑盒收藏接口。网页负责正常登录与请求签名，采集器只接收指定只读接口的返回条目，校验账号、offset连续性和末页；不猜测或枚举帖子ID。列表摘要不当成完整原文，正文只为新身份排队。正常网页停止在短页时最多核对一个实际next offset，不自造签名，拒绝或超时就保留未完成。接口缺失时兼容回退仅限专用收藏容器，不能从整个main或推荐流捡链接。

可选补齐模式将本次接口返回的旧未完成材料交给同一个采集队列，续读时也可补齐已登记但暂停的来源；本轮重复ID只登记一次。已完成、回收和永久删除记录不会被批量重采。验证前已收到的有效分页先保存，再停止；分页末尾和正文成功分别记录。

`app/store.py` 是本地状态源。原始来源与独立第一层材料分表保存；采集状态和处理状态分开。重新采集保留旧版本、批注和处理状态，正文变化会使不再适用的整理结果失效。任务队列及逐页进度可追溯；断点续读与新一轮最新收藏核对是不同操作。

同一规范来源只对应一条原始记录。永久删除留下规范来源的 SHA-256 指纹、原 ID、平台和时间，不保存已删原文或链接；同步跳过该指纹。远端不再收藏不触发本地删除。旧版本确有删除事件和本机备份时，可恢复来源指纹；没有历史证据时不能凭空重建。

个人运行目录为 `data`，包括数据库、按平台和材料 ID 分开的来源包、字幕、图片、版本、处理结果、模型、会话和本机 outbox。它们都在 `.gitignore` 中；代码仓库不带示例收藏数据库或真实内容。

## 处理与材料包

第一步依据原文和本人批注，分别生成调用资料或消化暂存的独立记录，不要求 AI。第一层处理记录保留来源快照、方向和批注版本；原始来源仍可回看。之后可在这一层自己加工，或主动让 AI 结合明确选择的相关笔记整理，结果先待本人审查。

`app/obsidian.py` 管理 Markdown 知识库根和相对目录，`app/knowledge.py` 只读取本人选定目录/笔记，不递归扫描整库。二级默认进入主题下的材料专区，人工知识稿是另一项明确选择，不自动改写既有正文。界面的速览由 `app/reading_preview.py` 计算，仅从原文或字幕摘句，不持久化为整理结果，也不进入后续 AI 或导出。

推送分两步：预览冻结版本、Markdown、附件清单、路径及哈希；确认核对哈希、材料修订、相关笔记及目录配置后才写入。预览后批注、目录或原文改变需要重新预览。确认有幂等回执，本机导出与真正外部系统执行状态分开。

`app/vault_files.py` 记录每份已确认包的具体文件和 SHA-256，迁移、回收、恢复、永久删除只操作这些归属明确的文件。文件日志和 SQLite 共同记录提交状态，中断后恢复；人工修改、共享附件、同名冲突、链接越界会停止。迁移更新本包相对图片与来源链接，核对后清理旧托管位置；不删除其他材料仍在使用的文件。

## 信任边界

平台页面、评论、字幕、模型结果都是不可信来源内容，不是工具执行指令。正文显示转义 HTML，外部链接及下载地址检查协议与公网地址，托管路径只允许知识库内普通相对目录。写请求验证本机来源和 `X-Local-Request` 请求头。登录态不进入 Markdown、AI 输入或公共 API 响应。

Windows 会话使用 DPAPI 加密；可选 Chrome 扩展只导出本人选定平台的快照，不请求全部网站访问、不扫描密码、没有外部网络请求。平台校验仍在实际访问时完成，Cookie 文件存在不代表登录有效或已读完全部收藏。
